# 无人作战飞机初步设计工具（Qt 桌面程序）

这是一个使用 **C++17 + Qt Widgets** 开发的桌面原型，参考方欣瑞《无人作战飞机概念方案总体参数优化研究》第二章的部分思路编写。

简单来说：程序把设计要求、飞行任务和相关参数整理到界面中，进行初步重量估算，并用图表展示不同性能要求之间的关系。

## 1. 论文主要研究什么？

论文研究的是：怎样形成一个飞翼式无人作战飞机的概念方案，再对方案进行分析、评价和优化。

- **第二章：形成初步方案。** 明确设计要求，选择布局和发动机类型，初步估算重量、推重比和翼载荷，确定初始布局与布置。
- **第三章：综合分析。** 建立参数化几何模型，分析发动机、气动、重量、性能、操稳、雷达散射截面和成本等方面。
- **第四章：综合评价。** 用层次分析法，把不同方面的表现综合成评价结果。
- **第五章：优化与工具集成。** 利用代理模型等方法开展总体参数优化，并将各模块集成为辅助设计工具。

第二章主要回答“初始方案大致是什么样、基本参数如何初步确定”，为后面的深入分析提供起点。

## 2. 这个程序目前在做什么？

当前程序主要对应第二章 **2.4 节“基本参数初始估算”**，并提供相关输入和结果展示界面。

| 界面或功能 | 通俗说明 |
| --- | --- |
| 设计要求 | 集中填写速度、高度、距离、载荷、起降和机动等要求 |
| 任务剖面 | 用表格描述一次飞行经过的各个阶段；默认有 8 段，可增加、删除和修改 |
| 气动 / 发动机 | 集中填写估算需要的气动和发动机参数 |
| 重量估算 | 反复更新估计值，给出最大起飞重量、空机重量和燃油重量 |
| 计算结果 | 显示是否收敛、迭代记录，以及各任务段前后的重量 |
| 性能约束图 | 展示巡航、盘旋、爬升、起飞和着陆要求对应的限制关系 |
| 图上交互 | 点击图中的位置，查看该点对应的各项裕度 |
| 项目保存 / 加载 | 用 JSON 文件保存和恢复输入参数与任务表格 |

几个常见名词：

- **任务剖面**：一次飞行任务的阶段清单。
- **迭代**：用上一次估算结果继续计算，直到前后变化足够小。
- **收敛**：迭代结果已经趋于稳定；它不等于模型已经得到实测验证。
- **翼载荷**：单位机翼面积承担的重量，图中单位为 N/m²。
- **推重比**：推力与重量之比，没有单位。
- **裕度**：所选参数相对某项要求的余量；负值表示按当前模型尚未满足该项要求。

## 3. 与论文的对应关系和当前范围

| 论文第二章的内容 | 当前项目的实现情况 |
| --- | --- |
| 设计要求、任务剖面 | 有输入界面和可编辑任务表格 |
| 气动布局选型、发动机选型 | 可录入部分参数，尚未实现完整选型流程 |
| 最大起飞重量估算 | 有简化的重量迭代计算 |
| 推重比、翼载荷估算及界限线图 | 有简化的约束计算与交互图表 |
| 气动布局参数及总体布置方案 | 尚未实现几何建模和内部布置 |

**目前应把它理解为“参考第二章思路制作的初步估算与展示原型”。**

代码采用了简化模型和经验系数，默认任务分段也没有逐段复现论文。部分输入参数尚未完整参与计算，例如高度尚未用于动态更新大气模型。因此，界面中存在某个输入框，并不代表相应分析能力已经完整实现。

图中的推荐点由预设规则生成，不是论文后续章节中的综合优化结果。项目尚未包含第三至第五章的完整几何建模、多学科分析、综合评价和优化功能，也没有完成与论文算例的逐项数值一致性验证。

## 4. 代码放在哪里？

### 界面语言与单位

界面以中文为主，长度使用 m，时间使用 s，质量使用 kg，力使用 N，速度使用 m/s，翼载荷使用 N/m²，耗油率使用 s⁻¹（即 1/s）。马赫数、推重比及各类系数标注为无量纲量。

结果界面将以 kg 表示的量称为“质量”；论文和部分代码名称仍沿用航空领域常见的“重量”说法。结果表格只读，结果摘要可以选中复制。

上述约定针对界面。现有核心数据结构和 JSON 文件仍保留 km、min、每小时等原有单位，界面读写时进行换算，不能直接把 JSON 中的数值当作界面单位使用。

| 文件或目录 | 作用 |
| --- | --- |
| `src/main.cpp` | 启动程序、创建主窗口 |
| `src/core/DesignTypes.h` | 定义输入参数、任务段和计算结果的数据结构 |
| `src/core/WeightAnalysis.cpp` | 重量估算和任务段重量变化计算 |
| `src/core/ConstraintAnalysis.cpp` | 性能约束、推荐点及裕度计算 |
| `src/ui/MainWindow.cpp` | 界面、按钮操作、结果表格和 JSON 文件读写 |
| `src/ui/ConstraintPlotWidget.cpp` | 使用 Qt 自带的 QPainter 绘图，处理图上点击 |
| `tests/core_tests.cpp` | 核心计算的基础测试 |
| `CMakeLists.txt` | CMake 构建配置 |
| `UCAVDesigner.pro` | qmake 工程配置 |

核心计算代码位于 `src/core`，不依赖 Qt；界面代码位于 `src/ui`。目前绘图使用 Qt 自带功能，不需要额外安装 QCustomPlot。

## 5. 怎样打开和运行？

### 使用 Qt Creator（推荐）

1. 安装 Qt 5.15 或 Qt 6，并安装对应的 C++ 编译工具链。
2. 在 Qt Creator 中打开 `CMakeLists.txt` 或 `UCAVDesigner.pro`。
3. 选择与 Qt 版本匹配的构建套件（Kit），例如 MinGW 或 MSVC。
4. 点击“构建”，成功后点击“运行”。

### 使用 CMake 命令行

在已配置好 Qt 和编译器的终端中，进入项目根目录后执行：

```bat
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

三条命令分别用于配置工程、编译程序、运行基础测试。基础测试通过不代表已经完成论文模型验证。

如果提示找不到 Qt，需要在配置时指定实际安装路径，例如：

```bat
cmake -S . -B build -DCMAKE_PREFIX_PATH=C:/Qt/6.7.0/mingw_64
```

上面的路径只是示例，需要替换为自己电脑上的 Qt 路径。如果已有 `build` 目录来自其他电脑或不同编译器，请换一个新的构建目录，并同步修改后续命令中的目录名。

### 使用 qmake 命令行

在对应的 Qt MinGW 命令行环境中执行：

```bat
qmake UCAVDesigner.pro
mingw32-make release
```

如果使用 MSVC，应改用匹配的构建工具，或直接通过 Qt Creator 构建。

更多 Windows 构建与打包信息见 [Windows 构建说明](docs/windows_build.md)。
